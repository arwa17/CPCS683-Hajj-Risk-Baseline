# Hajj Crowd-Risk Prioritization
**CPCS 683 — Advanced Artificial Intelligence**  
Arwa Al-Zahrani · Atheer Al-Sharif · Batool Al-Sulami

## Research study
A controlled comparison of a **Single-Agent** baseline and a **Multi-Agent** system for simulated Hajj crowd-risk prioritization.

- **Task:** Assess crowd, health, and environmental observations; return LOW, MEDIUM, HIGH, or ABSTAIN.
- **Single-Agent:** One Gemini generalist analyzes all three domains.
- **Multi-Agent:** Three Gemini specialists (Crowd, Health, Environment) supply reports to a shared, deterministic coordinator.
- **Controls:** Same 36 synthetic cases, reference-label policy, model configuration and seeds (11, 42, 77).
- **Safety:** Human review remains required; this is a course simulation, not an operational Hajj safety system.

## Experiment and results
The golden set includes **36 team-authored synthetic cases** and policy-derived reference labels. Saved evaluation: **216 runs** (36 cases × 3 seeds × 2 conditions) with Gemini 3.5 Flash-Lite at the recorded temperature of 1.0.

| Metric (mean ± sample SD across 3 seeds) | Single-Agent | Multi-Agent |
|---|---:|---:|
| Decision coverage | 80.56% ± 0.00 pp | 79.63% ± 1.60 pp |
| Selective accuracy on issued decisions | 100.00% ± 0.00 pp | 100.00% ± 0.00 pp |
| Valid reports | 97.22% ± 0.00 pp | 97.22% ± 2.78 pp |
| Model calls per case | 1.05 ± 0.02 | 3.00 ± 0.07 |
| Mean latency | 3.27 ± 2.65 s | 9.56 ± 7.90 s |

**Finding:** Multi-Agent did not demonstrate a coverage advantage on this synthetic evaluation and required more model calls and time. Selective accuracy excludes abstentions, so 100% is not all-case accuracy.

## Project files
- `m5/m5_agent.py`, `m5/m5_policy.json` — single/multi agent behavior and fixed scoring policy.
- `m5/m5_data/` — frozen cases, reference labels and SHA-256 manifest.
- `m5/m5_finalize.py`, `m5/scoring.py` — automated evaluation and seed-level scoring.
- `m5/results/m5_runs.jsonl` — saved experimental traces.
- `m5/results/m5_scores/` — M5 result tables (re-generated by the scorer).
- `m6/build_m6.py` — comparative results and failure analysis.

## Data provenance and limitations
The experiment uses **team-authored synthetic scenarios**, not the Kaggle Hajj/Umrah dataset or real incident records. Reference labels follow a disclosed classroom policy and were not independently expert-validated. Model seeds are best-effort: exact regeneration through the hosted API is not guaranteed. This measures agreement with a synthetic prioritization policy, **not real-world incident detection**.

Background: N. Samrgandi, *Multi-Agent Crowd-Risk Prioritization for Large-Scale Events: A Hybrid ML–Agent Approach*, IJACSA 17(7), 2026. [DOI: 10.14569/IJACSA.2026.0170738](https://doi.org/10.14569/IJACSA.2026.0170738).
